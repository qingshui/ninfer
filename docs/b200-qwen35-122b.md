# Qwen3.5-MoE-122B on B200

Build target, conversion, serving behavior and acceptance checks for running the
Qwen3.5-MoE-122B ModelOpt NVFP4 checkpoint on a single B200 (`sm_100a`). Option spelling and
defaults come from each program's `--help`.

## Build

```bash
CUDACXX=/usr/local/cuda-13.4/bin/nvcc cmake --preset b200-release
cmake --build --preset b200-release --parallel 160
```

`NINFER_TARGET=b200` selects x86_64 with `NINFER_CUDA_ARCHITECTURES=100a`. The configure log
prints `NInfer target: b200 (x86_64, sm_100a)`. Passing a different
`CMAKE_CUDA_ARCHITECTURES` fails with `b200 requires CMAKE_CUDA_ARCHITECTURES=100a`. The
`rtx5090-*` and `dgx-spark-*` presets are unchanged. Outputs are `ninfer`, `ninfer-serve` and
`ninfer-perplexity` under `build/b200-release/`. GPU specialization is chosen at build time.

## Convert

```bash
python3 tools/convert/convert.py <checkpoint_dir> <output.ninfer> --recipe qwen3_5_122b_nvfp4
```

The entry-point name and flags above are indicative. Check `--help` of the converter for the
exact spelling, including `--device`, `--rows-per-chunk` and `--source-cache-mib`.

Recipe `qwen3_5_122b_nvfp4` (listed in [weight conversion](weight-conversion.md)):

- Experts: two expert-major banks per layer, gate/up interleaved `(256, 2048, 3072)` and down
  `(256, 3072, 1024)`. Format `nvfp4`, method `import_encoded`, layout
  `batched_block_scale_k16_m128x4_v1`.
- Per-layer expert `input_scale` activation divisors live in one shared auxiliary tensor. Each
  expert use refers to it through `AuxiliaryReference`.
- Conversion fails if `input_scale` differs across the 256 experts of a layer, or if
  `weight_scale_2` or `input_scale` differ across q/k/v. `o_proj` is handled separately.
- `full_attention` q/k/v/o use NVFP4. The shared expert is decoded to BF16 (`cast_direct`). GDN
  weights, `mlp.gate`, `mlp.shared_expert_gate` and norms use `cast_direct`. `lm_head` and
  `embed_tokens` use Q8.

Source-side support in `tools/convert/`:

- `qwen3_5.py` detects the text prefix (`model.language_model.` or `model.`) from the tensors
  present. If neither exists it raises an error listing the candidate names.
- `qwen3_5.py::moe()` accepts fused 3D `experts.gate_up_proj`/`experts.down_proj` or per-expert
  `mlp.experts.E.{gate,up,down}_proj`. Both present, or a missing expert index, is an error that
  names the expert.
- `sources/compressed_tensors.py` treats a U8 `weight` with `weight_scale_2` as ModelOpt NVFP4.
  A U8 `weight` without `weight_scale_2`, or a scale shape other than `(n, k/16)`, is an error.

## Serve

```bash
CUDA_VISIBLE_DEVICES=1 build/b200-release/apps/ninfer-serve <artifact.ninfer> \
  --port 30100 --max-context 2042 --kv-dtype fp8
```

- `n` accepts any positive integer. `n=0`, negative or non-integer values return HTTP 400, as do
  values above the server limit. Streaming chunks use `choices[].index` 0..n-1, and non-streaming
  responses return n choices.
- With `stream_options.include_usage=true`, the last chunk before `[DONE]` has empty `choices` and
  a `usage` object. `prompt_tokens` counts one prompt. `completion_tokens` is the sum over the n
  completions. See [HTTP serving](serving.md).
- `serve` now defaults to `--max-concurrency 0` (auto lane fitting) instead of 8. Requests beyond
  the resolved lane count wait in the pending queue (`kDefaultServeMaxPendingRequests` = 1024)
  and are not rejected.

## Engine changes delivered with this target

| Area | Change |
|---|---|
| Prefill packing | `resolve_prefill_pack_tokens(chunk, token_capacity)` no longer clamps to `max_context`. `kPrefillPackChunks` is 8. See [prefill scheduling](maintainer/prefill-scheduling-and-packing.md). |
| GDN decode graph | Padding rows write state to a scratch row, so batches below the bucket replay the captured graph instead of running eager. |
| Prefill plans | Launch plans are prebuilt per (phase, token bucket). Misses and eager fallbacks are counted in observations as `prefill_plan_hits`, `prefill_plan_misses` and `prefill_eager_fallbacks`. |
| Pipeline | qwen3_5 reports capacity `{2,1}`: two compute frames in flight, with per-frame workspace. Other models stay `{1,1}`. |

## Registered 122B geometry

| Op | Shapes |
|---|---|
| Route / experts / shared / fused MoE | H=3072, 256 experts, top-8, I=1024, NVFP4 (shared expert also BF16) |
| split | NVFP4 n17408_k3072 segments {8192,512,8192,512}; BF16 n20480_k3072 segments {12288,8192} |
| projection | NVFP4 o_proj; BF16 (3072,8192) GDN out; Q8 (248320,3072) lm_head |
| GDN | (16,64) key/value heads, hidden 3072, fp32 state |
| Softmax attention | (32,2) heads, head_dim 256, all KV dtypes |

Unregistered geometry is rejected with an error that includes the geometry parameters.
